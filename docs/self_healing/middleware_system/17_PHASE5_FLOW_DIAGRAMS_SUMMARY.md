## 1. 정상 요청 흐름 (Happy Path)

```
HTTP Request
    │
    ▼
┌─────────────────────────────────────────────────────────────────┐
│ PHASE 1: 분산 추적 & 헬스체크 (DB 독립)                          │
│  [1] trace_id_middleware → trace_id 생성 "req-{uuid8}"          │
│  [2] HealthBridgeMiddleware → /health/l3 즉시 응답              │
└─────────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────────┐
│ PHASE 2: 트래픽 제어 & Self-Healing 진입                         │
│  [3] TieringMiddleware → EmergencyLevel 확인 (NORMAL=통과)      │
│  [4] SelfHealingMiddleware → CB 상태 확인 (CLOSED=통과)         │
└─────────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────────┐
│ PHASE 3: 사용자 추적 & Django Core                               │
│  [5] ActorContextMiddleware → actor_id, IP 추출                 │
│  [6-13] Django Core → Security, Session, Auth, CSRF 등          │
└─────────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────────┐
│ PHASE 4: Rate Limit & Pool 보호                                  │
│  [14] HybridRateLimitMiddleware → Redis 100req/min 체크         │
│  [15] PoolCircuitBreakerMiddleware → 캐시 기반 Pool 상태 확인   │
│  [16] PoolTimeoutMiddleware → 예외 감시 시작                    │
└─────────────────────────────────────────────────────────────────┘
    │
    ▼
╔═════════════════════════════════════════════════════════════════╗
║                    [VIEW 실행]                                   ║
║               비즈니스 로직 + DB 쿼리                            ║
╚═════════════════════════════════════════════════════════════════╝
    │
    ▼
┌─────────────────────────────────────────────────────────────────┐
│ PHASE 5: 응답 처리 & Audit                                       │
│  [4] SelfHealingMiddleware → status<400 → CB 성공 기록          │
│  [19] AuditMiddleware → 이벤트 수집 → 해시체인 기록 (맨 마지막!) │
│  [1] trace_id → X-Request-ID 헤더 추가, 컨텍스트 정리           │
└─────────────────────────────────────────────────────────────────┘
    │
    ▼
HTTP Response (+ X-Request-ID)
```

**핵심 포인트**:
- 19개 미들웨어가 순차 실행
- `HealthBridgeMiddleware`는 DB 없이 즉시 응답 (Worker Saturation 방지)
- `AuditMiddleware`는 **반드시 맨 마지막** (모든 이벤트 "낚아채기")

## 2. 예외 발생 흐름 (Exception Paths)

```
HTTP Request
    │
    ▼
┌──────────────────────────────────────────────────────────────────────────┐
│ 차단 지점 1: TieringMiddleware                                           │
│   EmergencyLevel != NORMAL && multiplier == 0                            │
│   ───────────────────────────────────────► 503 "LOAD_SHEDDING"           │
└──────────────────────────────────────────────────────────────────────────┘
    │ 통과
    ▼
┌──────────────────────────────────────────────────────────────────────────┐
│ 차단 지점 2: SelfHealingMiddleware (CB OPEN 체크)                        │
│   _is_cb_open() == True && POST/PUT/PATCH 요청                           │
│   ───────────────────────────────────────► 503 "CIRCUIT_BREAKER_OPEN"    │
│                                            + 🔒 선제적 DLQ 적재           │
└──────────────────────────────────────────────────────────────────────────┘
    │ 통과
    ▼
┌──────────────────────────────────────────────────────────────────────────┐
│ 차단 지점 3: HybridRateLimitMiddleware                                   │
│   is_allowed() == False                                                  │
│   ───────────────────────────────────────► 429 "RATE_LIMIT_EXCEEDED"     │
└──────────────────────────────────────────────────────────────────────────┘
    │ 통과
    ▼
┌──────────────────────────────────────────────────────────────────────────┐
│ 차단 지점 4: PoolCircuitBreakerMiddleware                                │
│   should_allow() == (False, reason)                                      │
│   ───────────────────────────────────────► 503 "POOL_CIRCUIT_BREAKER_OPEN"│
└──────────────────────────────────────────────────────────────────────────┘
    │ 통과
    ▼
╔══════════════════════════════════════════════════════════════════════════╗
║                              [VIEW 실행]                                  ║
╚══════════════════════════════════════════════════════════════════════════╝
    │
    ├── DB Exception ───────────► SelfHealingMiddleware catch
    │                              → CB 실패 기록
    │                              → DLQ 적재 (조건 충족 시)
    │                              → 503 "DB_CONNECTION_ERROR"
    │
    ├── Pool Timeout ───────────► PoolTimeoutMiddleware catch
    │                              → 503 "POOL_TIMEOUT"
    │
    └── HTTP 5xx 응답 ──────────► SelfHealingMiddleware 감지
                                   → CB 실패 기록
                                   → DLQ 적재 (조건 충족 시)
                                   → 원본 5xx 응답 반환
```

**핵심 포인트**:

| 예외 유형 | HTTP | DLQ | CB |
|----------|:----:|:---:|:--:|
| Emergency 차단 | 503 | ❌ | ❌ |
| CB OPEN (선제적) | 503 | ✅ | ❌ |
| Rate Limit | 429 | ❌ | ❌ |
| Pool 고갈 | 503 | ❌ | ✅ |
| DB Exception | 503 | ✅ | ✅ |
| HTTP 5xx | 원본 | ✅ | ✅ |

**DLQ 적재 조건**: `POST/PUT/PATCH` + `SELF_HEALING_DLQ_ELIGIBLE_PATHS` 매칭

## 3. 자동 복구 흐름 (Auto Recovery)

```
┌─────────────────────────────────────────────────────────────────────────┐
│                      Circuit Breaker 상태 전이                           │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│                        success_count >= 2                               │
│                   ┌──────────────────────────────┐                      │
│                   │                              ▼                      │
│            ┌──────┴──────┐                ┌───────────┐                 │
│            │  HALF_OPEN  │                │  CLOSED   │                 │
│     ┌─────►│ (테스트 중) │◄───────────────│  (정상)   │◄────┐          │
│     │      └──────┬──────┘  failure >= 5  └───────────┘     │          │
│     │             │                             │           │          │
│     │  elapsed    │ failure                     │           │          │
│     │  >= 60s     │ detected                    │           │          │
│     │  (Celery)   │                             │           │          │
│     │             ▼                             │           │          │
│     │      ┌───────────┐                        │           │          │
│     │      │   OPEN    │◄───────────────────────┘           │          │
│     └──────│  (차단)   │                                    │          │
│            └───────────┘                                    │          │
│                                                             │          │
│                                   manual_control("close")───┘          │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────┐
│                         Celery Beat 스케줄                               │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  ⏰ 2분마다: check_circuit_breaker_recovery                             │
│     └─► OPEN → HALF_OPEN 전환 (recovery_timeout=60s 경과 시)            │
│                                                                         │
│  ⏰ 5분마다: replay_batch_by_domain                                      │
│     └─► DLQ pending 항목 최대 50개 리플레이                              │
│                                                                         │
│  ⏰ 100ms마다: Pool 상태 갱신 (백그라운드 스레드)                        │
│     └─► _cached_pool_status 업데이트 (Non-Blocking)                     │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────┐
│                         복구 시퀀스 (전체)                               │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  장애 발생                                                               │
│      │                                                                  │
│      ▼                                                                  │
│  CB OPEN (요청 차단, DLQ 적재)                                          │
│      │                                                                  │
│      │ 60초 대기 (Celery Beat 체크)                                     │
│      ▼                                                                  │
│  CB HALF_OPEN (테스트 요청 허용)                                        │
│      │                                                                  │
│      ├─── 2회 성공 ──► CB CLOSED ──► 조건부 DLQ 리플레이 즉시 트리거    │
│      │                                                                  │
│      └─── 1회 실패 ──► CB OPEN (다시 차단, 60초 대기)                   │
│                                                                         │
│  ────────────────────── OR ──────────────────────                       │
│                                                                         │
│  5분마다 DLQ 배치 리플레이 (Celery Beat)                                │
│      └─► handler.can_replay() 확인 후 재시도                            │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

**핵심 환경변수**:

| 변수 | 기본값 | 설명 |
|------|:------:|------|
| `SELFHEALING_CB_FAILURE_THRESHOLD` | 5 | CLOSED→OPEN 실패 횟수 |
| `SELFHEALING_CB_RECOVERY_TIMEOUT` | 60 | OPEN→HALF_OPEN 대기(초) |
| `SELFHEALING_CB_SUCCESS_THRESHOLD` | 2 | HALF_OPEN→CLOSED 성공 횟수 |
| `POOL_CB_FAILURE_THRESHOLD` | 3 | Pool CB OPEN 전환 |
| `POOL_CB_RECOVERY_TIMEOUT` | 10 | Pool CB 복구 대기(초) |

│                 └────────────────────┬─────────────────────────┘            │

│              ┌───────────────────────┼───────────────────────┐              │
│              │                       │                       │              │

│       │  (2xx)    │          │(429/503)  │          │ (DB Error) │          │
│       └─────┬─────┘          └─────┬─────┘          └─────┬─────┘          │
